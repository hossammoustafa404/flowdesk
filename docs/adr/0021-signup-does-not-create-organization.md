# Sign-up does not create an Organization

A User may hold a seat in many Organizations at once, with one Org Role in each. Public Sign-up creates only the User. A verified User who is not a Super Admin creates an Organization in a separate act and becomes its Owner; there is no cap. With no seat, a Session may only create an Organization or accept an Invitation. Sign-in restores the last Active Organization only when that seat can still be used.

We rejected ADR 0004’s single act of User + Organization + Owner. That path minted an Organization the User did not ask for and made Invitation accept fail whenever the email already had one. We also rejected “leave this Organization to join another”: a Technician at one company can own another at the same time.

Creating an Organization makes it Active. Accepting an Invitation does so only when the User had none. Suspension and deactivation block that seat only, not the User’s login or their other Organizations. Sign-in does not restore a Deactivated seat or a suspended Organization. If every seat is unusable, the Session has no Active Organization. Leaving, removal, or deleting an Organization drops those seats and leaves the User and any other seats in place. The last Owner cannot leave, be removed, or be deactivated. Joining, besides creating the Organization, is only by accepting an Invitation. An Owner cannot invite someone who already has a seat there, including a Deactivated seat. One pending Invitation per email per Organization. It expires 48 hours after it is sent. Sending again while it is pending is refused and does not extend that time. It stops blocking a new one when accepted, rejected, cancelled, or expired. A Super Admin creates an Organization only together with an Owner Invitation and receives no seat. While that Organization has no seats, a Super Admin may cancel a pending Invitation and, once it is no longer pending, send another Owner Invitation. Once an Owner exists, only an Owner invites or cancels. Deleting an Organization ends its pending Invitations. If the Active Organization becomes unusable, the Session uses the same choice as sign-in.
